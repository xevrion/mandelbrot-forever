mandelbrot forever

a shape with an infinitely detailed edge. zoom in anywhere on the boundary and there is always more. it comes from one line of math repeated over and over.

wait, what is this

this is the mandelbrot set, probably the most famous picture in all of math. the black blob in the middle is the set itself, and the colors around it are how quickly each point outside it "escapes". the wild part is the edge: no matter how far you zoom in, it never gets smooth. there are tiny copies of the whole shape hiding inside its own edge, forever. it's genuinely infinite detail from a formula you could write on a napkin.

and here's the thing that gets people: the formula is z = z2 + c. that's it. you pick a point c, start z at zero, and keep squaring and adding. if z stays small forever, the point is in the set (black). if it blows up to infinity, it's outside, and the color tells you how many steps it took to blow up. every pixel on screen is that one calculation, done thousands of times.

what you're seeing: every pixel is a point c in the complex plane (x is the real part, y is the imaginary part). black means we iterated z = z2 + c and it never escaped, so it's in the set. colors mean it escaped, and the shade tells you how fast. bright fast-escapers are far from the set, dark slow-escapers are hugging the edge. the "detail" slider is the maximum number of iterations we try before giving up and calling a point black. deep zooms need more, cuz points near the edge take longer to decide. the hud shows your zoom level: 1x is the whole shape, and you can go past a trillion x before the numbers run out of precision.

how it's actually built (the whole thing is tiny)

this is the entire algorithm. for one pixel, given its point (cx, cy), count how many steps until it escapes:

function escape(cx, cy, maxIter){
  let x=0, y=0, i=0;
  while(x*x + y*y <= 4 && i < maxIter){
    const xt = x*x - y*y + cx;   // real part of z^2 + c
    y = 2*x*y + cy;              // imaginary part of z^2 + c
    x = xt; i++;
  }
  return i;
}

that's z = z2 + c written out with real and imaginary parts, cuz javascript has no complex numbers. the "escape" test is x*x + y*y <= 4, meaning once z gets further than 2 from the origin it's mathematically guaranteed to fly off to infinity, so we can stop early. that one fact is why the whole thing is fast enough to run in a browser.

why the colors are smooth and not banded

if you just color by the integer iteration count you get ugly hard stripes. the fix is a little trick called smooth coloring: after the point escapes, look at how far past 2 it got, and use that to add a fraction to the count. so instead of "escaped at step 37" you get "escaped at step 37.62". that fractional part is what makes the gradients silky:

// after the loop, if it escaped:
const log_zn = Math.log(x*x + y*y) / 2;
const nu = Math.log(log_zn / Math.LN2) / Math.LN2;
const smooth = i + 1 - nu;   // fractional iteration count

why zooming feels instant

the canvas renders in two passes. first a fast low-res version (every 4th pixel, then filled in as blocks) so you see something immediately, then a full-res pass on top. it also renders in horizontal strips using requestAnimationFrame so the browser never freezes, even at 3000 iterations. no web workers, no gpu, just being a little clever about the order.

why it eventually breaks

javascript numbers are 64-bit floats with about 16 digits of precision. zoom past roughly 1013x and the pixels stop being distinguishable, so you see blocks. that's not the fractal ending, it's the number type running out. real deep-zoom software uses arbitrary precision math to go to 10100x and beyond. that's on the try-later list.
